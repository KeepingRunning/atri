# 本地随机日常与固定睡眠

正式日程由 [schedule.py](../src/atri_bot/schedule.py) 读取 [日常素材库](../resources/daily_routines/README.md)。当前 116 份成品已获用户认可，每份包含两小时大日程和十二个十分钟小格。运行时不请求模型生成日程，不预生成下一窗口，也不使用向量检索。当前素材的制作与校验工具保留在 `experiments/daily_routines/`，不参与在线排班。

## 时间和随机选择

时区固定为 `Asia/Shanghai`。窗口采用自然偶数整点，启动于 18:35 时也使用 18:00–20:00，不从启动时间重新计时。

| 窗口 | 匹配素材标签 |
| --- | --- |
| 00–02、02–04、04–06、06–08 | 内置“睡觉”，不读取素材库 |
| 08–10 | 清晨、上午、不限 |
| 10–12 | 上午、不限 |
| 12–14 | 中午、不限 |
| 14–16、16–18 | 下午、不限 |
| 18–20 | 傍晚、不限 |
| 20–22、22–24 | 夜晚、不限 |

每个新窗口读取目录下的 JSON，筛选 `suggested_time_of_day` 与当前标签有交集的文件，然后用 `random.choice` 等概率选取。若还有其他候选，去掉上一份的 ID 后再抽；只有一份时允许重复。多标签条目在候选池中也只有一份，不增加权重。

同一窗口所有群共享一个选择，十分钟边界只换小格，最后十分钟仍使用本窗，不提前抽下一份。后台每 30 秒检查一次。Planner 模式在建立聊天快照时按实际时钟获取日程，规划与正文读取同一份背景；等待或重规划会建立新快照。旧模式在生成正文前获取。无需等到下一次后台轮询才刷新。

选择只考虑时间标签。`scene`、`participants`、`preconditions` 随大日程作为虚构场景说明传入，不作为现实条件检查；也不维护跨窗口的地点、伙伴、剧情阶段和事件完成状态。原作伙伴不等于群友，未来安排不等于已经完成的经历。

## conversation 注入

白天的消息处理为：

```text
接收、去重、记录 → 睡眠检查 → 按群收集一批消息
→ 等待模型槽位 → 睡眠检查 → 当前时间 + 大日程 + 当前十分钟小格 + 近一小时群聊快照
→ Planner 判断与按需查询 → Replyer 结合人设生成正文
→ 睡眠与快照过时检查 → 统一发送 → OneBot 回执
```

Planner 模式将日程放进聊天快照的 `schedule` 字段，两阶段共享它；旧模式放在回复 conversation 的 `system` 提示词中。大日程包含摘要、场景、伙伴、前提和各大阶段的绝对起止时间；小日程仅传此刻一格的活动、关注点、情绪及时间。其他十一格、出处原文、语料来源 ID、审核记录不进入提示词。

聊天历史通过时间戳独立筛选近一小时，不按 50 条截断，也不因某个日程需要而补入更早聊天。

例如 18:35 建快照取 18:30–18:40；若等待模型槽位到 18:40 才建快照，则取 18:40–18:50。同一快照的规划和正文使用相同背景，等待补充或重规划时更新。日程可用于自然回答“在干嘛”，不要求每次汇报。它不主动发消息，也不单独写成群聊历史；实际发送成功的回复仍按原有逻辑保存。

## 00:00–08:00 强制不回复

以下规则由 `schedule.sleep_enabled` 控制，默认 `true`。设为 `false` 后重启可临时夜间试聊：入口、模型和 OneBot 发送都放行睡眠检查，00:00–08:00 从“夜晚/不限”素材抽选（无候选则自由休息），不再注入睡眠背景。`schedule.enabled` 仍独立控制日程注入；恢复作息时把 `sleep_enabled` 改回 `true` 并重启。

睡眠判断由代码执行，区间为 `[00:00, 08:00)`，优先于 `at_only`、意愿规则、模型评分和失败降级。真正 @、引用机器人、名字呼叫也不能绕过。

- 夜间收到的允许群消息正常记录、去重，并保存 `kind="schedule"`、`reason="sleeping"` 的拦截记录；不加入回复队列，不调用意愿或回复模型。
- 午夜前入队、午夜后才处理的消息丢弃。即使机器休眠、任务直到次日 08:00 后才恢复，也按接收日期识别，不补发。
- 每次聊天模型 HTTP 提交前检查睡眠，包括意愿判断的内部重试。若构造上下文或首次请求期间跨过午夜，不再提交后续请求，不走规则降级。检查限定在当前消息任务内，不影响其他任务或手动 `test-api` 诊断。
- 午夜前已经提交的模型请求可能继续完成；返回后检查时间，夜间结果不会发出。因此“跨午夜的待处理回复”只指午夜前开始的工作，不表示夜间新消息会发给 LLM。
- 真正发送前再次检查；OneBot 提交处还有最后一道检查。午夜前已经提交的消息无法撤销，QQ 实际送达或回执可能晚于午夜。
- OneBot 重连补推的消息若自带夜间时间戳，也不会在早上得到补发回复。缺少时间戳的消息按本机接收时刻判断。
- 08:00 起只处理新消息，不主动发送起床通知。Planner 自动快照排除夜间收到的聊天；存盘仍保留，明确查历史时可以检索。旧 willingness / at_only 的历史选择行为保留。

`enabled = false` 只关闭清醒时的日程背景，固定睡眠规则仍生效。

## 持久化、删改和故障处理

`data/schedule/state.json` 使用版本 2，原子保存当前窗口起点、选中 ID、时区和素材目录。不再保存模型生成内容、未来计划或重试次数。当前窗口重启时从仍有效的候选中恢复该 ID，避免重抽；旧版本缓存直接忽略并替换。

每个窗口重新读素材，重启也重新读。已删除、修改时段或损坏的文件不会在下次加载时继续使用；同一窗口已经载入内存的内容不会热切换。需要立即应用删改可重启服务。重复 ID 的所有同名候选会被排除。

运行时检查 120 分钟覆盖、2–5 个连续大阶段、12 个连续十分钟格、活动归属、必填文字和时段标签。坏文件逐份跳过并记警告，其他条目照常使用。没有匹配素材时使用内置“自由休息”，不向其他时段借条目，也不调用模型补写。夜间直接使用内置睡眠，无需素材库有效。

落盘失败会记录错误，本进程继续复用内存中的选择；由于未成功保存，下一次重启不能保证恢复同一份。后台任务随应用启动和关闭，不访问模型会话。

## 配置与预览

```toml
[schedule]
enabled = true
timezone = "Asia/Shanghai"
routines_dir = "resources/daily_routines"
```

`routines_dir` 相对于配置文件目录，也可填写绝对路径。没有本节时使用上述默认值。旧的 `schedule.model` 为兼容旧配置而忽略，可直接删除。修改配置后重启生效。

```sh
# 本地抽选，无需 API 密钥；不连接 QQ、不读群历史、不改正式状态
uv run atri test-schedule --at 2026-09-11T18:35:00+08:00
uv run atri test-schedule --at 2026-09-12T00:00:00+08:00
uv run atri test-schedule --at 2026-09-12T08:00:00+08:00
```

预览使用临时状态，打印整窗十二格和当前背景。每次运行独立抽选，可能与正式服务当前选择不同。省略 `--at` 使用当前上海时间；无时区的输入也按上海时间处理。睡眠时预览显示内置睡眠背景，但正式消息会先被拦截，不会调用聊天模型。

素材库里的历史 `status: pending_user_review` 和 `review` 是制作记录；这批已经用户认可，运行时不以它们筛除条目。成品仍可直接手动删改。离线制作方式见 [素材制作说明](../experiments/daily_routines/README.md)。

```sh
uv run python -m unittest discover -s tests -v
```

测试覆盖整库格式、时段匹配、避免连续重复、窗口和十分钟边界、同窗恢复、旧缓存忽略、删改素材、空库及落盘失败、关闭任务；也模拟了午夜与 08:00、夜间 @/引用、队列和模型跨午夜、发送前落盘跨午夜、OneBot 提交拦截和次日不补发。本地 HTTP/WebSocket 集成测试检查完整聊天回执流程，并确认服务启动、选日程和独立预览都不产生日程 API 请求。没有启动真实 QQ 服务或进行实群发送验证。
